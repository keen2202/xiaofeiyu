## 一、审查结论

**本期需求已形成方案级覆盖，可作为实施评审基线；尚不能认定真实 SDK 适配、功能实现和运行验收已完成。**

推荐保留“轻核心＋可选适配器＋独立生产执行”架构：核心统一管理身份、任务、审批、防重、额度及事实账本；IM 传递经过授权的命令；生产端只生成产物；发布独立创建任务并审批；停机迁移不自动重放旧任务或未知操作。

该方案通过按需加载和独立进程控制默认依赖与故障影响，不要求微服务、消息中间件或分布式调度。但独立进程不减少同机实际渲染开销，也不等于安全沙箱；性能和资源占用尚未测量。

## 二、功能与契约覆盖

以下“已设计”均不表示代码已实现。

| 领域 | 本期设计与边界 | 主要依据 |
|---|---|---|
| 轻核心、日记与任务状态 | 稳定 workspace/平台账号身份，Task/Operation/Execution 分离，统一审批与账本；日记由完整事件事实重建；只管理本插件任务 | SPEC §4～7、§10、§14、§26 |
| B 站读取、评论、私信 | 热门/搜索、详情、字幕、热评；评论草稿/审批/显式 auto；白名单私信发送。不包含收件箱、评论/@自动监听 | SPEC §8、§11～13 |
| 公共及平台契约 | 版本、请求幂等、inputHash、稳定账号/内容引用、能力声明和标准回执；平台私有字段与核心隔离 | SPEC §18、§21 |
| IM 接入 | 可信通道身份＋业务权限、消息防重、人工挑战审批、自有任务查询/取消、持久 outbox；不开放凭据、执行器、迁移或人工补录管理 | SPEC §22 |
| 视频生产与产物 | 固定 script/assets/voice/render/validate 阶段；ArtifactRef、执行回执、取消/恢复、预算与检查点；首个 profile 为 local-slideshow-v1 | SPEC §23～24 |
| 独立发布 | 受管视频产物进入独立 PublishTask，重新核验与审批；Manual/External 回执分别记账，不包含原生 UPOS | SPEC §15 |
| 停机迁移 | prepare/export/release/import/validate/activate，完整账本与素材搬运、源端禁写、目标默认暂停、按能力核验和最新账本回滚 | SPEC §25 |
| 后续扩展 | X、抖音及 remote 后端仅预留契约和 Mock 验收要求，不安装 SDK、不运行远程服务，也不计为真实接入 | SPEC §21、§24.4、§26 |

首期生产目标是使用已导入图片/片段、用户脚本和可选音轨/字幕合成真实 MP4 与封面。商业文案生成、生图、TTS 仅为可选扩展，不承诺默认“一句话自动生成全部素材并发布”。IM 桥接也不等于 B 站私信收件箱。

## 三、关键问题及已修订规则

| 审查问题 | 修订后的约束 |
|---|---|
| Cookie 更新导致账号防重命名空间变化 | 使用 platform＋whoami 核验的稳定账号 ID；Cookie 摘要仅为凭据修订号，同账号换凭据不清额度、永久键或 unknown |
| 热事件截断、切号覆盖日记、正文与索引不一致 | 2000 条仅为热缓存；持久 pending/归档保留事实，日记路径按 scope 隔离，采用版本检查和可恢复提交 |
| 本机信任、模型文本或 approved:true 被当成人工许可 | 通道认证与主体权限分离；审批绑定原 Task、输入摘要、主体、修订及过期挑战，不能由请求正文自报权限 |
| 任务已接纳、进程退出或部分成功被误报完成 | accepted 不等于 succeeded；未决集合与 isSettled 单独管理；有 unknown 不得清理或伪装为安全取消 |
| 免费执行、通知和平台写被混为同一类操作 | 平台写/付费使用 OperationContext；本地阶段使用 ExecutionDispatchContext；通知使用 OutboxDispatchContext，共享派发栅栏但不重复创建 Operation |
| 生产完成直接发布，或 External 未知结果转 Manual 绕过核查 | 生产与发布分任务、分审批；Manual 在可信人工补录时创建确认操作，External 核查必须更新原 Operation |
| 迁移冻结妨碍收尾，或复制旧备份造成重复外发 | prepare 冻结新业务及派发但允许在途回执落账；封存后不改快照，源端交接后持久禁写，目标不自动重投旧 Task/outbox |
| 目标未激活被用作直接恢复源端的例外 | source release 后，无论目标是否激活，都须先持久禁用目标及旧票据，再用目标所持最新账本反向交接；状态或账本不可得则保持阻塞 |

这些是文档规则的修正，不是已经通过运行测试的代码修复。

## 四、未验证项与交付门槛

| 未验证项 | 必须补充的证据 | 影响范围 |
|---|---|---|
| DSH IM SDK、消息结构与人类身份证明 | 先只读核对实际接口，再经单独授权验证消息→原任务→人类决策→状态回信；Mock 不能替代 | T16.2、T12.1；不阻塞无关离线模块 |
| 可信本地人类管理入口 | 验证主体及交互证明来源，不能仅凭 --confirm、同 OS 进程或模型声明授予审批/迁移权限 | T14、T10 的敏感入口 |
| 真实本地视频生产 | 显式配置受信媒体工具与目录，实际生成可解码 MP4、可读封面并核验 manifest/hash | T17.3；生产完成的必需门槛 |
| B 站与 External 发布器 | 只读身份/接口核验，以及单独授权、最低额度的实际回执验证 | T12.2；未授权时明确未实测 |
| Windows/Linux 真实迁移 | 双根目录/双实例测试必做；跨 OS 另验路径、工具绑定、账本连续和禁写交接 | T18、T12.3；模拟不能冒充真实跨 OS 通过 |

安全保证以遵循协议的实例和可信本地程序为前提。不承诺抵抗同一 OS 账号的任意恶意代码，也无法在没有中心协调服务的情况下阻止人为复制目录、绕过交接同时启动两端。付费 Provider 若无法约束成本上限，不开放自动调用。

## 五、已完成的文档检查

本次复核确认：

- 18 项架构决策已编入设计稿；42 条新增需求均在 TASKS 的逐条矩阵中对应工作项和验收条件。

- 本地生产的任务依赖不包含 B 站、Browse、IM 或商业 Agent；发布不依赖生产 Runner，可使用已导入视频。
- 示例配置与 SPEC 默认配置结构一致；业务功能默认关闭，生产/发布保持干跑，生产付费上限为零。
- 复核时 src 仅有空的 modules 目录，test 无测试文件；未运行插件功能测试、真实 IM、平台写入或真实媒体/迁移验收。

**以上是文档与计划的静态验证，不是功能测试通过，也不是真实服务可用性证明。**
